# 任务拆分器

将用户需求转化为**不冲突的多线程代码任务**，每个任务包含精确修改位置、标准化提示词、自检清单。

## 触发条件

用户描述一个改动需求后，说出以下任一触发词：
- "拆一下"
- "拆任务"
- "多线程"
- "给提示词"
- "帮我拆"

## 输出文件

**所有输出统一写入** `3.0/TASK_PROMPTS.md`，覆盖式写入（每次新任务替换旧内容）。

写入后告知用户："已写入 [3.0/TASK_PROMPTS.md](3.0/TASK_PROMPTS.md)，点击打开即可复制。"

**必须使用 Markdown 可点击链接格式**：`[3.0/TASK_PROMPTS.md](3.0/TASK_PROMPTS.md)`，让用户在 VSCode 里直接 Ctrl+点击打开。

用户只需点击蓝链打开文件，看到 `copy` 代码块逐个复制给 Codex 执行。

## 标准流程

### Phase 1：代码探索

**目标**：定位所有受影响文件和具体代码行。

**必须做**：
- 阅读受影响的 HTML、JS、CSS 文件
- 搜索关键函数名、CSS 类名、变量名，确认所有引用点
- 确认数据从哪里来、流向哪里

**不可做**：
- 不猜测代码位置——grep 确认
- 不看一个文件就说"应该是 XXX 的问题"

### Phase 2：根因诊断

**目标**：解释"为什么坏了"。

**输出格式**：
```
## 问题诊断

| 问题 | 根因 | 影响范围 |
|------|------|---------|
| 进度条消失 | var(--cyan) 在重写 CSS 后被删除 | 漏斗、项目、品线三处 |
```

### Phase 3：线程拆分

**目标**：按文件边界拆分，确保零冲突。

**拆分规则**：
- 线程 A：只改 `styles.css`（视觉/样式）
- 线程 B：只改 `app.js`（逻辑/结构）
- 线程 C：只改 `index.html`（入口/语义）
- 线程 D+：仅在其他独立文件需要修改时新增（如 `review-mock-data.js`）
- **禁止两个线程修改同一文件的同一区域**

### Phase 4：输出提示词

**格式**：每个线程一个 ```` ```copy ```` 代码块。

**每个代码块必须包含**：
```
## 任务：一句话概述

### 背景
为什么要改，当前什么状态

### 涉及文件
- 文件路径（只读/修改）

### 修改清单
1. 文件：XXX，位置：第N行附近
   - 改前：`旧代码`
   - 改后：`新代码`
   - 原因：XXX

### 不改的边界
- 不改 XXX
- 不碰 XXX

### 自检清单
- [ ] 检查项 1
- [ ] 检查项 2
```

### Phase 5：验收指南

**每个线程结束时输出**，作为独立的 ```` ```copy ```` 代码块：

```
## 集成验收清单

### 控制台
- [ ] 无 error / warning

### 功能
- [ ] 四个 Tab 切换正常
- [ ] 数据卡片无 undefined/NaN

### 视觉
- [ ] 1920px 四列等宽
- [ ] 375px 单列无横向滚动

### 不通过处理
任一 ❌ → 退回对应线程，通过前不得合并
```

## 关键规则

### 必须遵守
- **先定位根因，再写提示词**——用 grep 确认每个引用点，不猜测
- **线程之间零冲突**——按文件边界拆分，不改同一文件
- **不改的边界必须写清楚**——每个任务声明"不碰 XXX"
- **每个代码块可独立复制**——不依赖其他代码块的上下文
- **所有验收项可直接在浏览器验证**——不写"检查是否正确"，写"打开页面 → 点击 X → 看到 Y"

### 不可做
- 不输出半成品提示词（缺文件路径、缺行号）
- 不跨线程合并修改（线程 A 改 styles.css 的同时线程 B 也改 styles.css）
- 不在提示词中写"酌情修改""自行判断"之类模糊表述
